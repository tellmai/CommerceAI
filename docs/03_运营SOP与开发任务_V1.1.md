# 运营 SOP 与任务状态 V1.1

首版用于单人本地研究及测款记录。模拟数据和真实历史用于验证软件，当前没有接入用户的淘宝店铺，不把软件测试视作选品策略已经盈利。

## 每个候选的操作顺序

1. 登记有权使用的数据来源及证据，再导入或手工录入关键词、平台商品和报价。确认指标口径及日期，缺失不填零。
2. 创建商品和标准 SKU，将同款审核与相似替代品分开。记录价格地区、数量、优惠、运费和时效。
3. 关联关键词及主备供货报价。分别确认代发、运费、服务费、库存/交期承诺、退换货和有效期。
4. 先进入研究、待买样阶段；买样前没有样品结果是正常情况。主备分别检验尺寸、材质、包装、质量和履约，记录结果及证据。
5. 利润中心保存正常和联合压力情景。正常采购及运费与主供报价一致；退款净损失不含广告；报价改变后重算。
6. 记录知识产权、资质、商品安全、履约审核。已确认阻断要有新的解除证据；高评分不跳过审核。
7. 补充人工研究评估，提交评分，查看覆盖率、区间、缺失因子及证据。待核验和低样本分数不能当作成功概率。
8. 条件满足后人工推进到可测款，创建预算、止损、截止日期及观察目标，再开始测款。软件不代替用户发布商品或购买样品。
9. 每日按渠道记录曝光、有效点击、支付单及广告；导入脱敏订单，补齐采购、运费、退款和实际费用。未知成本留空。
10. 核对广告分摊，区分未成熟和成熟结算订单。根据样本、预算、履约及贡献，人工选择继续研究、暂停、淘汰或扩大。

## 周期检查

- 每日检查供货有效期、异常退款、预算、待结算费用和当前风险，不只看销量。
- 每周复查同款价格和供应商承诺，保留主图/价格/投放变更。数据过期后重新核验。
- 每月按SKU和支付订单窗口复盘成熟贡献，不将未来数据补入历史评分。修改策略时创建新版本，保留失败和不确定结果。

## 公开历史数据

公开历史空间中的 UCI 交易以 GBP 计，销售及取消时间保留原始依据。缺少采购和广告等成本，完整贡献保持未知；取消发票没有可靠原订单对应关系时标记 UNMATCHED。不得转成当期淘宝搜索人气、代发成本或真实经营成绩。

## 工程任务对照

| 任务 | P0 实现 |
|---|---|
| D00 数据核验 | UCI 官方许可、原文件摘要及真实小样已核对；用户实际商家权限和平台接口仍待后续验证 |
| D01 工程骨架 | 前后端、PostgreSQL迁移、鉴权、Compose、原生备用启动及CI |
| D02 导入 | CSV/XLSX、映射、预览、错误行、检查点、幂等、来源撤销 |
| D03 策略 | 五类策略、三值规则、可比窗口、机会比及趋势 |
| D04 商品SKU | 标准规格、平台商品、同款审核、时效及零售报价聚合 |
| D05 供应链 | 主备供货、费用、退换约定、样品和证据 |
| D06 经济性 | Decimal利润、CAC、压力情景、现金需求及六组基准 |
| D07 评分风控 | 七因子、未知区间、版本快照、风险优先、新证据解除 |
| D08 审核界面 | 中文工作台、研究详情、人工迁移、并发版本校验 |
| D09 测款复盘 | 计划、漏斗、订单修订、成熟贡献、广告分摊、导出 |
| D10 验证维护 | 独立数据库测试、真实历史对账、10万行测试、备份恢复工具及浏览器验收 |
| D11–D13 | AI报告、授权平台接口、监控预警继续归P1，未伪造实际平台连接 |

具体通过项与环境限制以 [验收报告](验收报告.md) 为准。系统 Docker 安装需要管理员权限；当前机器以原生 PostgreSQL 模式运行。
