# CommerceAI 工程实施规格 V1.1

本规格描述已实施的单人本地 P0。P1 已补充四平台报价、采购分析与数据服务适配，实时接口需授权账号验证，见 [找货与比价](联网选品与比价.md)。AI 报告、定时监控和多租户仍待后续实施。

## 模块及依赖

后端分为 API 与身份校验、类型合同、数据仓储、纯计算规则、研究评分、工作流、导入队列和经营报表。路由调用应用服务，纯计算模块不访问数据库、HTTP 或模型。前端使用 Vue 3、TypeScript、Element Plus 和 ECharts，通过同源 `/api/v1` 访问后端。

PostgreSQL 保存当前业务实体、关系、不可覆盖的修订、审计、导入批次、任务和会话。业务实体采用 JSONB 载荷，由各资源独立 Pydantic 合同校验；关系镜像到 `entity_link`，复合外键同时校验数据空间及记录标识。这样既保留类型合同和强制隔离，也让供应链、审核及评分共享版本机制。此结构替代 V1.0 的逐表 DDL 草案，详见 ADR。

## 数据合同

每条实体有 UUID、数据空间、类型、版本、创建及更新时间。来源、原始文件、映射、证据、订单及评分都保留来源链路。支持的合同和全部字段由 [字段字典](字段字典.md) 及 [OpenAPI](openapi.yaml) 给出。

- 空间为 `demo/public/live`，请求使用 `X-Workspace`，默认 demo。任何跨空间读取及关联均拒绝；不是只在页面上加筛选。
- 金额最多四位小数，API 输入使用字符串，内部 Decimal，展示 HALF_UP 两位。订单净费用和其他净变动费用允许负数表示返还；采购退款单独为非负退款额。
- 未知费用为 null，确认没有发生才为零。比例为 0–1；统计窗口为左闭右开。
- 时间输入必须包含时区；无时区文件由导入设置赋予来源时区后转 UTC。公开历史保留原文件、来源时区及原币种。
- 已售、已拼、评价和估算销量分别保存类型、单位、原文、精度及窗口；下界不能作为精确销量。集中度人工评估必须标记精确口径且至少10条可比样本。
- 当前业务自然键去重，修订追加到历史表；字段业务标识不可直接修改。订单按来源、外部脱敏订单键及明细键去重，不能重复归属其他实验。

## 导入和后台任务

上传限制默认20MB、10万行；仅接受 CSV/XLSX。支持工作表、原始列映射、统一值、比例单位、UTF-8/GB18030 和来源时区。CSV/XLSX 的公式不能作为原始字段输入，宏、非法文件名及过大的压缩内容被拒绝。

上传只生成预览和批次，最多预览20行，不写正式业务记录。确认后按空间、来源、文件哈希、类型、有效映射和设置计算幂等键。worker 先流式校验并暂存标准记录，超过行数上限时不提交业务记录；普通错误行生成报告，其余允许部分成功。

每1000行提交一次，事务内同时推进检查点和计数。故障重试从已提交检查点恢复，不重复计数。来源权限在每批写入前重新校验。原始文件保留哈希，记录保存批次及行号；公开数据脚本同样走此导入队列。

任务状态：QUEUED → RUNNING → SUCCEEDED/FAILED/CANCELLED。PostgreSQL `FOR UPDATE SKIP LOCKED` 领取，120秒租约，校验及分批写入时续租；令牌防止旧 worker 在重领后继续提交。最多3次指数退避；最后一次租约失效转失败。取消保留已经提交的批次，并在界面显示实际计数。

## 研究策略及评分

五类策略：蓝海长尾、趋势增长、跨平台价差、差评痛点、关联组合。策略使用 PASS/FAIL/UNKNOWN：AND 中失败优先，OR 中通过优先；任一策略通过可作为入池依据。痛点及组合采用有证据的人工核验，P0 不生成 AI 评论。

趋势必须同来源、类目、口径、相等且相邻的完整窗口；七日策略要求至少4个连续周窗口，另核验30日增长。机会比只作为相对研究指标，零分母和不兼容窗口不产生无穷大。

七因子权重保持需求20、竞争15、利润25、供应链15、增长10、售后10、差异化5。连续变量在同类目、来源和窗口内取平均名次百分位，至少30个有效样本；不足时仅使用显式配置的区间，没有配置则未知。演示区间只在 demo 配置中启用。

供应链按履约40%、质量与样品40%、主备20%；售后按损失率反向60%、质量/使用风险40%；差异化由人工输入并记录理由及证据。每个因子缺少必要子项则整个因子未知，不重分配权重。

覆盖率为已知因子权重之和；不足80%只提示待核验；达到80%但不完整仅显示分数区间，不出正式等级。完整且闸门通过后按阈值降序判断 S≥85、A≥75、B≥65、C≥50、D<50，不依赖 JSON 对象键顺序。分数、证据置信及归一化样本情况需结合查看，不视作成功概率。

评分冻结配置、输入值、可比样本、证据及记录版本、算法版本和输入哈希。重放使用保存的输入，不用当前数据覆盖历史。输入、策略或证据更新及过期会标记历史评分待核验；重新评分创建新的快照。

## 匹配、报价和审核

标准 SKU 与平台商品核验包装数量、材质、尺寸及配置要求的其他属性。支持基本 mm/cm/m、g/kg 单位换算。硬冲突或缺失必要属性不得确认为同款；数据库约束一个平台 SKU 只能对应一个已确认标准 SKU。

同款审核冻结双方规格版本。修改规格后旧确认失效，需要重审。每个链接只取最新适用口径的有效报价，并最多贡献一个可得价格；报价必须同币种、地区和包装数量。优惠资格未核验、运费未知、过期、批发或代发价格均列出排除原因，不进入零售价格带。返回数量、最低、P25、中位、P75、最高，少于5条提示样本不足。

阶段与审核结论分开：买样不要求已有样品；样品通过和进入测款分别执行对应条件。进入测款要求主备不同供应商、有效核验报价、样品、四类风险审核、正常/压力利润及一致的采购运费。压力参数至少有一项不利变化且不得改善其他参数。来源、证据或报价更新后重新校验；解除已确认阻断必须有新证据或新证据版本。

## 利润和复盘

每支付订单期望贡献：`E=(1-r)*(P-C-F-B-T)-r*L-A`，CAC 上限为未扣广告的期望贡献。L 不含广告，已扣可回收采购款等；部分退款通过实际账本逐项记录。固定费用、人工等另计，贡献不等同最终净利润。

实际贡献为实付收入减客户退款、采购，加采购退款，再减运费、包材、净费用、广告及其他净变动费用。未知任一必要费用时不生成完整贡献；成熟且结算完成才进入最终贡献统计。

广告按支付日及渠道等额分配到订单，再等额分配到该订单所属候选明细；四位小数尾差归稳定排序最后一条。渠道支付单数与已导入订单数不一致时拒绝分摊。分摊策略及来源漏斗版本写入订单修订。

实验记录预算、止损、日期、目标点击、假设及评分引用。预算耗尽、亏损超过上限或审核失效时提示暂停；样本和成熟费用不足时结论为不确定。只有成熟贡献为正、观察样本和当前审核满足条件时，才允许人工选择扩大。

## 接口、身份及兼容

本地单用户口令、HttpOnly 会话、同站 Cookie、写请求 CSRF 校验；无公开注册及多角色权限。登录有限速，凭据不写入日志、导出或 Git。默认只绑定127.0.0.1。

统一分页与结构化错误；写入需要身份校验及审计。记录修改、同款审核和候选迁移携带 `expected_version`，冲突409。来源及证据不可跨空间使用。API 生成前端类型，迁移生成 SQL；初始代码不存在旧客户端兼容负担。

部署、备份、当前测试结果和未验证项见 [运行与维护](运行与维护.md) 与 [验收报告](验收报告.md)。
